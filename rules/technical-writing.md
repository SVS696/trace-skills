# Как применять языковые скиллы в TRACE

Используйте установленный языковой скилл. Для русского текста выберите `utr`, для английского — `simplified-technical-english`. Откройте его `SKILL.md` в каталоге скиллов текущей среды. Для Codex общий каталог — `~/.agents/skills/`. В инструкции указаны нужные правила, словарь, примеры и источники. Оба скилла поддерживаются в личном каталоге SVS. [УТР](https://github.com/SVS696/svs-skills/tree/main/plugins/technical-writing/skills/utr) · [Simplified Technical English](https://github.com/SVS696/svs-skills/tree/main/plugins/technical-writing/skills/simplified-technical-english)

Если проект использовал ссылки из прежнего установщика TRACE, сначала проверьте, что новая независимая установка открывает `SKILL.md`. Посмотрите цель прежней ссылки в пользовательском или проектном каталоге `.agents/skills/` либо `.claude/skills/`. Ссылку, которая указывает на прежний каталог языка внутри TRACE, переключите на установленный скилл. Если общий скилл уже доступен проекту, лишнюю проектную ссылку можно удалить. Сохраните собственные каталоги и ссылки проекта с другими целями.

1. Пишите черновик сразу на языке результата. Возьмите из источника условие, исполнителя, действие, силу требования, исключения и проверяемый результат. Сохраните причину решения там, где она объясняет поведение. Для сокращений, имён полей и статусов используйте обозначения проекта.
2. Если проект требует `humanizer` или читатель затрудняется применить текст, укажите редактору конкретную трудность. Редактор может изменить порядок изложения и пояснить связь между условием и действием. Для рекламного текста используйте `copywriting`, когда пользователь запросил такую работу.
3. После последней редакторской правки передайте исходник и изменённый текст в режим проверки выбранного языкового скилла. Разберите штатный случай и существенное исключение. Если две трактовки дают разный результат и источник допускает обе, запишите открытый вопрос. Для упомянутого в источнике владельца решения укажите его роль.
4. Выполните сверку на текущей стадии TRACE. Назначенный проверяющий оценивает понятность и смысл той же версии в обычном раунде ревью. Для ограниченного задания укажите в списке материалов входной файл языкового скилла и конкретные справочники, которые потребуются исполнителю. Для формальной проверки добавьте исходный стандарт нужной редакции.

Например, клиент вправе повторить запрос, а сервис обязан вернуть исходный идентификатор. Если редактор заменил «вправе» на «должен», верните клиенту исходное право. Если источник не определяет признак повтора, запишите этот вопрос отдельно.
