# TRACE course check

## Назначение

Course check останавливает длинный ход достаточно рано, чтобы parent проверил не только
формальную корректность процесса, но и направление работы. Время является сигналом для
проверки, а не доказательством проблемы: сложная задача может идти долго и правильно.

Автоматический временной trigger предоставляет Smoke Break. Он фиксирует начало turn и
после завершения tool call периодически добавляет model-visible reminder. TRACE владеет
решением по reminder; Smoke Break не меняет workflow-state и не оценивает качество.

## Когда выполнять

Выполнить один checkpoint перед следующим tool call, если runtime передал elapsed-time
reminder о длительности текущего turn. `Smoke break:` — известный совместимый префикс,
но решение определяется capability, а не вечной формулировкой стороннего текста. Не
запускать отдельного агента и не перечитывать весь case. Использовать уже загруженный
исходный запрос, текущий stage/route, active diff и последние результаты.

Reminder не приходит во время одного долгого tool call или простоя. После его завершения
проверка выполняется на первом доступном checkpoint; TRACE не имитирует фоновый таймер.
Course check принадлежит parent. Reminder внутри делегированного узкого запуска не
считается checkpoint parent: агент возвращает только свой bounded progress, а parent
выполняет проверку при следующей доступной точке со своим outcome и frontier.

## Проверка

1. **Outcome.** Сформулировать исходный пользовательский результат одним предложением.
2. **Frontier.** Назвать один текущий item, hypothesis, failing check или gate. Если их
   несколько, работа уже расширилась и требует сужения.
3. **Progress.** Назвать новый подтверждённый факт, закрытый diff item, receipt или
   прошедшую проверку с прошлого checkpoint. Число команд, агентов и прочитанных файлов
   само по себе progress не доказывает.
4. **Drift.** Проверить, не выросли ли scope, число механизмов, файлов, review-классов или
   предположений без нового evidence либо решения пользователя.
5. **Falsifier.** Выбрать самый дешёвый следующий шаг, способный опровергнуть текущую
   гипотезу или подтвердить ближайшую границу. Ещё один широкий discovery не считается.
6. **Verdict.** Выбрать ровно один вариант:
   - `CONTINUE` — есть измеримый progress, frontier не расширен и следующий шаг проверяем;
   - `BACKTRACK` — путь держится на неподтверждённой предпосылке, повторяет тот же класс
     сбоя или чинит механизм, появившийся из предыдущего исправления;
   - `ASK` — продолжение требует решения, authority, scope expansion или внешнего входа;
   - `STOP` — outcome достигнут либо безопасного следующего шага без нового решения нет.

## Защита от превращения reminder в фон

- Два последовательных checkpoint без нового подтверждённого progress запрещают
  `CONTINUE`, даже если команды и агенты продолжают успешно запускаться.
- Повтор того же класса ошибки после смены локального патча требует `BACKTRACK`, а не
  ещё одного исключения в процессе.
- `BACKTRACK` означает возврат к последней подтверждённой границе и новый минимальный
  falsifier. Он не разрешает destructive rollback или удаление пользовательской работы.
- `ASK` не разрешает внешнюю запись, публикацию, merge, deploy или расширение scope.
- Course check не заменяет `P18`, `P19`, independent review и обязательные receipts.

## Наблюдаемый ответ

Parent оставляет одну короткую commentary-строку, чтобы checkpoint переживал compaction:

```text
TRACE course check — <VERDICT>: outcome=<...>; frontier=<...>; progress=<...>;
drift=<none|...>; next=<falsifying step|user question|terminal reason>.
```

Это сообщение не является workflow-artifact, lifecycle receipt или доказательством
готовности. В следующем checkpoint оно используется только для сравнения progress.
