# Аналитическое исследование

Уточни вопрос, цель, получателя и границы исследования. Для простой справки дай ответ сразу. Для исследования прочитай [правила TRACE](../../rules/process-kernel.md) и правила проекта. Проект определяет источники, формат отчёта, владельца решения и порядок публикации.

1. Укажи проблему, последствия, цель, пользу и решение, которое предстоит принять. Если предлагаешь изменить систему, опиши изменение поведения. Для описательного исследования укажи вопрос и назначение результата.
2. По каждому источнику запиши версию или дату, запрос, значимый фрагмент и результат поиска. Отметь отрицательные результаты и недоступные источники. Различай наблюдения, интерпретации, допущения и предложения. Сообщения, расшифровки и память проверь по источникам. Полномочия устанавливай отдельно. Когда данных достаточно, заверши широкий поиск. Возобнови его для конкретного пробела или проверки, которая может опровергнуть вывод.
3. Для каждого существенного пробела выбери действие. Проверь доступный источник, задай владельцу решения самостоятельный вопрос или с разрешения запроси данные у внешнего владельца. Отложить можно деталь, которая не влияет на наблюдаемое поведение или приёмку. Укажи противоречия и их влияние на вывод. Вопрос остаётся открытым до получения ответа.
4. Сравни уместные варианты по цели, ограничениям, стоимости, риску и обратимости. Для изменения примени [правила выбора границ](../../rules/solution-boundary.md) и `simplicity-spec`. Сохрани подтверждённую совместимость и обоснованную возможность расширения. Удали механизмы без требования.
5. Напиши целый отчёт, затем уточни отдельные разделы. Соблюдай [правила технического языка](../../rules/technical-writing.md). Для существенного вывода укажи источник. Запиши варианты, рекомендацию, принятое решение, его основание, участников и ссылку на согласование. Сохрани эти сведения в доступном проектном документе. Если решение заменили, укажи причину прежнего выбора и новое решение.
6. Сверь ответ с вопросом, источниками и границами. Примени `humanizer` для аудитории. После редакторских правок сверь технические формулировки и выводы с источниками по правилам технического языка. Для содержательного результата передай точную версию независимому проверяющему. Предоставь ему ограниченный набор источников и доступ на чтение. Следуй правилам ревью проекта. Для revmux используй действующий цикл исправлений и предел в пять раундов. Авторская проверка дополняет независимую. Предмет проверки — качество анализа. Укажи остаточные замечания и недостающие данные.
7. Передай результат по [правилам передачи](../../rules/handoff-contract.md). Если публикация разрешена, прочитай опубликованный текст и сверь его с исходным. Если источников недостаточно для вывода, объясни, что проверено, чего не хватает и какие данные изменят ответ.

## Переход к другой работе

Для постановки передай в `spec-preanalysis` проверенные факты, проблему, цель, предварительные истории и критерии, решения и открытые вопросы. Постановка требует предварительной записки, решения о составе статей и согласования. После согласования используй `spec-workflow`. Для реализации нужен явный маршрут `delivery`.

Для изменения системы аналитик может передать в OpenSpec обоснование и требования к поведению. Зафиксируй точную версию нормативного документа проекта. Техническое проектирование и задачи реализации относятся к разработке. Вводи собственную схему анализа только при подтверждённой потребности в отдельном артефакте.

Дизайнер проверяет сценарии взаимодействия и макеты. Аналитик задаёт наблюдаемые критерии приёмки и риски. QA определяет тесты, данные, среду и регрессионные проверки, затем выполняет их на реализации. Подключай нужных участников по задаче. При необходимости аналитик и дизайнер уточняют сценарий вместе.

Получатель должен видеть ответ, проверенные источники, статус решения и ревью, границы вывода и следующее действие. Регистрируй согласование постановки, реализацию, QA, слияние, развёртывание и приёмку по отдельным свидетельствам. Для исследования шаблон постановки, кейс TRACE, OpenSpec и таймер не требуются.
