# Список исправлений по revmux

Для новой постановки создай список только после полного результата revmux и разбора замечаний по правилам простоты. До ревью автор и редактор правят рабочую статью напрямую. Номер этапа в списке относится к итоговой статье.

```json
{"schema":1,"stage":4,"items":[{"id":"D4-001","source_finding_id":"F-1","target":"article.md#RULE-1","change":"Исправить переход в итоговой статье и сверить описание в связанном блоке","reason":"Переход в статье расходится с подтверждённым правилом","status":"open"}]}
```

1. Включи каждое принятое замечание. Исключи отклонённые замечания и правки без исходного замечания. Основным предметом каждой правки остаётся проверенная статья. Дополнительные файлы перечисли в той же правке.
2. Внеси весь пакет изменений и выполни автоматические проверки.
3. Зарегистрируй применение через `resolve-review --item ID --receipt RECEIPT`. Подтверждение относится к байтам обновлённой статьи. До проверки оно показывает только применение.
4. Выполни `article-updated` и запусти следующий обычный revmux. Успешный чистый раунд подтверждает исправление. Отдельную точечную проверку и `verify-review` не запускай.
5. Для отказа от правки требуется фактическое решение пользователя или проекта. Зафиксируй его отдельно от подтверждения исправления.

В старых кейсах могут оставаться поэтапные списки и предыдущие подтверждения. Старые команды доступны для совместимости. Для перехода старого кейса нужен запрос. Для разработки используй правила `delivery-workflow`.
