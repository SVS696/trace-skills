# Установка и внедрение TRACE

## Установка

1. Из корня рабочей копии выполните `python3 scripts/install.py install`. Установщик подключает скиллы и копирует роли для Codex и Claude Code.
2. Выполните `python3 scripts/install.py verify`. Установщик сверяет пути, владельцев и контрольные суммы. Он может завершить прерванное копирование своей роли. Устаревшую копию он удаляет только при совпадении записи владельца и хеша. Если файл принадлежит другому инструменту или содержит местные изменения, разберите расхождение до замены. Для намеренной замены неверной ссылки команды `install` и `install-project` принимают флаг `--repair-links`.
3. Выполните `python3 scripts/rule_library.py validate`. Команда сверяет контрольные суммы зеркал и проверяет доступность всех 100 методических правил по маршрутам.

HÆZE использует общую установку. RTL использует локальный адаптер, который Git исключает из проекта. [Настройки проектов](project-adapters.md)

## Перед началом разработки

Установите Node.js версии 20.19.0 или выше. TRACE поддерживает OpenSpec от 1.13.0 до версии ниже 2.0.0. Для проверенной версии выполните:

```bash
npm install -g @fission-ai/openspec@1.13.0
python3 scripts/openspec_bridge.py
```

Для нового рабочего проекта выполните `openspec init --tools codex,claude --no-animation`. Сохраните существующие настройки. Установщик TRACE не запускает npm и не инициализирует проект. Пакет OpenSpec создают при входе в конкретную разработку. Для анализа установка CLI не требуется. Начатые кейсы разработки продолжают записанный порядок. [Контракт OpenSpec](../skills/delivery-workflow/references/openspec.md)

## Напоминания в длительной работе

Установите исходный плагин Smoke Break для Codex или адаптер TRACE для Claude Code. Рекомендуемый интервал для обоих инструментов — 15 минут. В файле `~/.smoke-break.env` это значение задаёт строка `SMOKE_BREAK_INTERVAL_MS=900000`. Проверьте выбранные среды до начала длительной работы. [Установка плагина](../integrations/smoke-break/README.md)

```bash
python3 scripts/smoke_break_dependency.py verify --runtime codex --runtime claude
```

Если плагин отсутствует, автоматическое напоминание по правилу `P23 COURSE-CHECK` недоступно. Ранее сохранённые подтверждения TRACE сохраняют силу.

## Переход со старого процесса

При внедрении TRACE команда зафиксировала исходные коммиты Vigers и Delivery Engineering и сохранила незакоммиченные изменения Vigers локально. Затем команда установила роли, проверила команды во временных каталогах и подготовила перечень старых кейсов и черновики сообщений без отправки. Команда отключила старые точки входа, обновила маршруты RTL и HÆZE, провела независимые проверки инструкций и сверила опубликованную версию с GitHub.

Если старый кейс с `composition: article-first` или `composition: hybrid` создан до перехода на текущий процесс, `caseflow` направляет его в `legacy-case-migration`. Сохраните предметные материалы. Новую постановку начните с полного черновика по шаблону на стадии 1.

## Оценка пилота

В первом пилоте используйте действующий шаблон проекта. По каждому кейсу запишите:

1. Объём загруженных материалов на каждой стадии.
2. Число повторно открытых расхождений между блоками.
3. Размер каждой группы исправлений.
4. Число раундов до закрытия замечаний `critical` и `major`.
5. Число остановок по правилам `practical-risk`, `simplicity-brake` и лимиту пяти раундов.
6. Активное время работы и календарную длительность.
7. Долю замечаний, которые обнаружили только после стадии 4 или на ревью, хотя статья существовала со стадии 1.

Принимайте решение о расширении процесса по результатам 3–5 разных кейсов.
